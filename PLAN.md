## Decisions log

- _2026-07-09 (session 13)_ — **S17 flip semantics**: a flip is *this run's persisted action vs the ticker's immediately-preceding stored recommendation* (any prior run, matching digest panel-9), computed in-pipeline by reading `get_latest_actions` **before** step 6c writes — not by re-querying after persistence (which would see this run's own rows). Only successfully-persisted recs can produce a flip; a first-ever recommendation for a ticker is not a flip. Known edge: a rec skipped by the 4h dedup window still reports its flip (the comparison is in-memory) — harmless, since the summary is a per-day upsert and the later run wins.
- _2026-07-09 (session 12)_ — **Token usage declared a user priority; Message Batches API adopted for the per-ticker calls** (user choice among: batch API / prompt trims / suggestions-only). The 63 requests are independent and latency-irrelevant on a daily cron, so the 50% batch discount is the dominant lever (~$0.15 → ~$0.08/run). Prompt caching stays off the table (prompts are far below Haiku's 4096-token minimum cacheable prefix). Remaining smaller levers documented in HANDOFF_12: trim summary input (send only the first sentence of each reasoning, ~−3K tokens), cap reasoning at 2 sentences (output tokens cost 5× input), fewer news/Reddit lines.
- _2026-07-09 (session 12)_ — **Simplified predictions view = a new standalone `predictions_dashboard.json`** (user choice over extending the digest or track-record): the digest stays the deep-dive, track-record the accuracy analytics, predictions the "what does the model say right now" view.
