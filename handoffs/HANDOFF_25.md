3. **The chosen slice — patterns→prompt feedback loop** (design-first; user approved the design then the build):
   - **Gate — `select_patterns_for_prompt`** ([src/analysis/patterns.py](../src/analysis/patterns.py)): takes the raw `get_latest_patterns` row (the `patterns` JSON column arrives from pymysql **as a string** — parsed here), keeps status ∈ {**CONFIRMED, REVISED**} (never NEW — unproven; never RETIRED — dead), **confidence ≥ 0.7** (inclusive), sorts by confidence desc, caps at **3**. Constants `PROMPT_PATTERN_STATUSES` / `PROMPT_PATTERN_MIN_CONFIDENCE` / `PROMPT_PATTERN_MAX`. Malformed anything (bad JSON, non-list, non-dict entries, missing name/description, non-numeric confidence) shrinks the result — worst case `[]`, never an exception that could cost a run.
   - **Render — `_patterns_block`** ([src/analysis/claude_client.py](../src/analysis/claude_client.py)): Spanish block "Patrones históricos del propio sistema (minados de sus aciertos y errores pasados; solo patrones confirmados con alta confianza)" + one `- name: description` line per pattern + the framing instruction "Pondera estos patrones únicamente si aplican a este ticker. Son sesgos observados en el historial, no reglas absolutas: la evidencia actual del ticker manda." Placed **between the horizon block and the standing-call (prev_action) block**; `""` when empty.
   - **Threading**: new optional `patterns` param (default `None`) on `_ticker_request_params`, `analyze_ticker`, `analyze_tickers_batch` and on `run_ticker_recommendation` / `run_ticker_recommendations_batch` ([src/analysis/recommendation.py](../src/analysis/recommendation.py)) — **run-global, parallel to `macro_signals`** (it's not per-ticker data). Default None keeps every legacy caller byte-identical.
   - **main wiring** ([src/main.py](../src/main.py)): right after `get_latest_actions`, a fail-soft block reads `select_patterns_for_prompt(get_latest_patterns(conn))` and logs either "Injecting N mined pattern(s) into ticker prompts: <names>" or "No confirmed high-confidence patterns to inject into ticker prompts"; an exception logs and leaves `[]`. Passed positionally into the 6b batch call.
   - **The loop ships inert by design**: the 07-12 seed row is all-NEW, so the gate yields `[]` and production prompts don't change by one byte. It **self-activates** the first time a Friday mining run emits CONFIRMED/REVISED at ≥ 0.7 — deliberately not front-running Friday's confirmation (uniform block for all tickers; keyword relevance-matching on free-text Spanish patterns was rejected as fragile).
