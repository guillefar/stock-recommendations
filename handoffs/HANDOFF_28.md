### 3. The slice: the mechanical excess gate

Two new **required** fields on the pattern structured-output schema in `generate_pattern_analysis`:

- **`excess_return_pp`** (number) — the excess of the bucket the pattern rests on, copied from the stats.
- **`primary_action`** (enum `BUY|SELL|HOLD|WATCH|AVOID|NONE`) — needed because "exclude WATCH" has to be mechanical, and a name is not machine-readable.

`select_patterns_for_prompt` ([src/analysis/patterns.py](../src/analysis/patterns.py)) gained `PROMPT_PATTERN_MIN_ABS_EXCESS = 1.0` and `PROMPT_PATTERN_EXCLUDED_ACTIONS = {"WATCH"}`. Design decisions, settled with the user:

- **Magnitude, not sign.** Excess is direction-blind — SELL's −9.4pp is its *best* evidence. A `excess > 1` rule would silently drop the system's most skilful action. (The per-action sign rule was rejected for a subtler reason: `BUY es un lastre` is a pattern asserting BUY *fails*, which −3.0pp genuinely supports, so "BUY requires positive" would block a true pattern. Action alone doesn't tell you a pattern's claim direction.)
- **WATCH excluded at any magnitude**, because it asserts no direction, so its excess reports drift rather than skill.
- **Filters run before the top-3 cap**, so the cap chooses among patterns that already qualify.
- **Fails closed.** A pattern missing either field is dropped. Every stored set (ids 1,2,3,5) predates the fields, so **injection stops on deploy and resumes at the first post-merge Friday mining run.** Intended: all of them rest on a corpus graded before the s26 re-grade *and* before this session's quote_type fix.

**The unfinished half:** the gate *filters* on excess, but the survivors are still **ranked by the miner's confidence**, which is a hit-rate judgement. That is precisely session 27's complaint, still standing. **Ranking by |excess| is the pinned next slice.** (On this output the two orderings happen to agree on the top 3 — luck, not design.)

## Learnings

Written at the user's request. The arc: s26 — a loop amplifies bad data. s27 — fixing the data doesn't fix the loop. **s28 — a fix you keyed on a field is only as good as that field, and a gate is only as good as what it ranks.**

1. **A fix keyed on a column inherits that column's gaps.** Session 26 correctly identified that ETFs need different bands and correctly measured the 0.30× factor — then keyed it on `quote_type` and wrote `None → unscaled` with the comment "the conservative default". Two ETFs were NULL, so for them the bug survived its own fix, silently, through two sessions and a full audit. **When you branch on a data field, enumerate its actual values in production before deciding what the fallback means** — `SELECT quote_type, COUNT(*) GROUP BY quote_type` is ten seconds and would have shown `NULL: 2` in session 26.
2. **"Conservative default" is a claim about direction, and it needs checking.** Falling back to unscaled stock bands *sounds* cautious — wider bands, fewer confident verdicts. For a 1.3%-a-month fund it isn't cautious at all: it auto-passes every HOLD and auto-fails every WATCH, which is a strong, wrong opinion. **A default is only conservative relative to a distribution; name the distribution.**
3. **The artifact you're building a filter for can be the artifact in your filter's input.** The gate was designed around `WATCH × (otro)` at +10.6pp — the case that proved a naive magnitude test insufficient. That number turned out to be *itself* a bug, not a hard case. Had the design gone straight from HANDOFF_27's description to code, it would have been tuned against a phantom. **Before treating a data point as the constraint your design must satisfy, check that the data point is real.**
4. **Verify the effect against the counterfactual, not against the before-state.** Session 27's lesson was "validate the effect, not the mechanism", and session 28 nearly declared victory on "the gate blocked the bad pattern" — true, and nearly meaningless, because the top-3 cap would have blocked it anyway. The question that mattered was *what would have been injected without the gate*, which is one function call and turned out to be **the identical set**. **"X was blocked" is not evidence the blocker did anything; compare against the world where it doesn't exist.**
5. **Filtering is not selecting.** The gate enforces "no pattern rests on a bucket that merely tracked the market", which is a floor. What actually reaches production is decided by the *ranking*, and the ranking is still the miner's confidence — a hit-rate judgement, the exact thing session 27 flagged. **A guarantee about the candidate set says nothing about the choice among candidates.** Half the problem was solved; the handoff says which half.
6. **The model reproduces a known error even when handed the corrected number.** `WATCH × (otro)`: 0% hit rate, `exceso +11.0pp` in its own evidence string, labelled "colapso sistemático". Same failure as session 27, one session later, after the prompt was extended to say these fields decide injection. **Two independent runs is enough to call it a property rather than a bad draw** — stop spending prompt words on it and let the gate carry it.
7. **A metric's invariant catches structural changes, not just arithmetic ones.** Overall excess stayed exactly 0.0pp through the cohort re-keying and the 72-row re-grade. That single assertion confirmed the re-cohorting didn't corrupt the accumulation, for free, at every step. **Cheap invariants earn most of their keep during refactors, not at the moment you write them.**
8. **When the calendar gates the evidence, say so and hand it forward intact.** Two of the five TODO steps needed production runs that hadn't happened — the session started the same day the previous one ended. The temptation is to substitute something adjacent and report it as coverage. **Report the gap; a handoff that says "not runnable, carried whole" is worth more than one that quietly widened its scope.**
9. **Pausing a feedback loop is a legitimate, cheap experiment.** Failing the gate closed stops injection until the next Friday mining run. That is not just safety against the contaminated stored sets — it produces the **no-injection control** that the BUY-suppression question has lacked for three sessions (07-31/08-03 injected the artifact set, the s27 dry-run injected the corrected set, and nothing has run with no block at all). **When a loop's effect is disputed, turning it off for one cycle is often the cheapest measurement available.**

## Invariants (don't break)

All of HANDOFF_27's invariants stand — in particular **excess is direction-blind** (negative = skill for SELL/AVOID) and **the market cohort is `(rec_date, ETF vs non-ETF)`**. New this session:

- **`src.quote_types` is the single place that corrects asset class.** Add an entry only for an instrument whose class is genuinely known and wrong at the source (check `yfinance` `Ticker.info['quoteType']` first). `resolve_quote_type` **only fills gaps** — never make it overrule a real source value. **Any change to the map changes stored verdicts and needs a `--regrade` with the user's sign-off.**
- **The overrides are applied at the DB read sites**, not at each consumer. If you add a query that reads `tickers.quote_type`, select `t.symbol` alongside it and pass the rows through `apply_quote_type_overrides` — otherwise that consumer silently regresses to the source table's NULLs.
- **The excess gate tests magnitude, never sign.** `abs(excess) >= 1.0`. A sign rule inverts SELL, the system's most skilful action. Test-pinned.
- **WATCH patterns are never injected**, at any excess. Test-pinned.
- **The gate fails closed.** A pattern missing `excess_return_pp` or `primary_action` is dropped, including via NaN. Do not "tolerate" a missing field for backward compatibility — the sets that lack it are exactly the contaminated ones.
- **Filters run before `PROMPT_PATTERN_MAX`.** Capping first would reserve slots for patterns the gate rejects.
- **The `_patterns_block` regime caveat still stays.** HANDOFF_26 conditioned removal on market-relative figures (done, s27); HANDOFF_27 on a mechanical gate (done, s28). **Both conditions are met and it should still stay** for at least one Friday — the s28 mining call shows the miner's prose is still hit-rate-driven even for patterns the gate approves.
- **The live DB is ahead of `main` until this branch merges.** The 72-row re-grade is already applied; `main`'s grader would push those two symbols back onto stock bands if `evaluate_outcomes` ran from `main`.
